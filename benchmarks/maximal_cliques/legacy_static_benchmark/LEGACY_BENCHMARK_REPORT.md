## 1. Executive Summary & Objective

In the algorithmic study of connected proper interval graphs $G = (V, E)$, enumerating or compactly characterizing the family of maximal cliques is a foundational primitive with widespread applications in chordal graph decomposition, maximum independent set computation, dominating set construction, and scheduling.

This report documents the design, verification, and empirical results of a dedicated benchmarking suite comparing three algorithmic paradigms:
1. **Algorithm A (Theorem-Based / Thesis Proposed):** Our implementation based on Chapter 3, Lemma 3.8 and Lemma 3.15 of the thesis, which builds the canonical distance tree $T(G)$ and identifies compact clique descriptors $[p_{\text{idx}}, c_{\text{idx}}]$ by scanning non-leaf parent nodes.
2. **Algorithm B (General Graph Baseline — Bron–Kerbosch with Pivoting):** The classic recursive backtracking enumerator adapted from Phase 5, equipped with Tomita pivot selection and $\mathcal{O}(1)$ closed interval-intersection adjacency testing.
3. **Algorithm C (Independent Domain Standard — Interval Sweep-Line):** A standard endpoint-sorting sweep-line algorithm operating directly on the $2n$ interval endpoints via Helly's property, completely independent of distance trees or thesis lemmas.

### Research Questions
- **RQ1 (Asymptotic Verification):** Does Algorithm A's core clique identification run in strictly linear $\mathcal{O}(n)$ time across all interval overlap profiles?
- **RQ2 (Core vs. Materialization):** At what point does explicit clique membership expansion ($\mathcal{O}(S)$, where $S = \sum_{j=1}^q |C_j|$) dominate the core identification time, and what is the exact compression advantage of compact descriptors?
- **RQ3 (Scalability Horizon of Bron–Kerbosch):** At what graph order $n$ does general backtracking with pivoting encounter its practical timeout limit ($> 3,000\text{ ms}$) on proper interval graphs?
- **RQ4 (Overlap Sensitivity):** How does increasing interval overlap (varying bandwidth $k = \lfloor W/d \rfloor$) affect preprocessing, core identification, materialization overhead, and direct end-to-end execution time?

## 2. Description of the Three Algorithms

### 2.1 Algorithm A — Theorem-Based (Lemma 3.8 & Lemma 3.15)
- **Mathematical Foundation:**
  - Let $G = (V, E)$ be a connected proper interval graph whose vertices are canonically indexed $1, \dots, n$ in non-decreasing order of left endpoints $\ell_1 \le \dots \le \ell_n$ (and consequently $r_1 \le \dots \le r_n$).
  - The canonical distance tree $T(G)$ is rooted at the leftmost interval $v_1$ (depth 0). Each subsequent vertex $v \in V \setminus \{v_1\}$ chooses as its parent the candidate $u \in N(v)$ with the minimum distance-tree depth, breaking ties by minimizing $\ell_u$.
  - By **Lemma 3.8**, for each node $u \in T(G)$, the subset $C(u)$ consisting of $u$, its children, same-level vertices to its right, and children of same-level vertices to its left forms a clique in $G$. When $u$ is a leaf, $C(u)$ is non-maximal and properly contained in the clique associated with its parent.
  - By **Lemma 3.15**, every maximal clique of $G$ is generated by a non-leaf parent node $p$ and its rightmost child $c \in C(p)$. In canonical order, this maximal clique is compactly defined as the contiguous index range $[p_{\text{idx}}, c_{\text{idx}}]$, containing all vertices with indices $v \in [p_{\text{idx}}, c_{\text{idx}}]$.
- **Execution Pipeline:**
  - *Preprocessing (`preprocessing_ms`):* Construct the canonical distance tree $T(G)$ using a monotonic two-pointer sweep in $\mathcal{O}(n)$ time, followed by level set computation and preorder/postorder traversals.
  - *Core Identification (`core_ms`):* Scan the $n$ sorted vertices. For each non-leaf parent $p$ (i.e., `childrenIds.empty() == false`), retrieve its rightmost child $c = \text{childrenIds.back()}$. Record the compact descriptor $[p_{\text{idx}}, c_{\text{idx}}]$ in $\mathcal{O}(1)$ time. Total core time: $\mathcal{O}(n)$.
  - *Materialization (`materialization_ms`):* Expand each descriptor into explicit vertex lists in $\mathcal{O}(c_{\text{idx}} - p_{\text{idx}} + 1)$ time. Total materialization time: $\mathcal{O}(S)$.

### 2.2 Algorithm B — Bron–Kerbosch with Pivoting (Tomita Heuristic)
- **Mathematical Foundation:**
  - Explores maximal cliques via depth-first backtracking over vertex partitions $(R, P, X)$, where $R$ is the currently accumulating clique, $P$ is the candidate set of vertices that can extend $R$, and $X$ is the set of already explored vertices that must not extend $R$.
  - **Tomita Pivoting:** To minimize branching, a pivot vertex $u \in P \cup X$ is chosen to maximize $|P \cap N(u)|$. Only candidates $v \in P \setminus N(u)$ are recursively branched upon.
- **Execution Pipeline:**
  - *Adjacency:* Evaluated dynamically in $\mathcal{O}(1)$ time via closed interval intersection ($[\ell_u, r_u] \cap [\ell_v, r_v] \ne \emptyset \iff \ell_u \le r_v \land \ell_v \le r_u$), bypassing an explicit $n \times n$ adjacency matrix.
  - *Safety Guard:* Every 500 recursive calls, the elapsed time is checked against a hard 3,000 ms wall-clock limit. If exceeded, the algorithm safely aborts and sets status `TIMEOUT`.
  - *Status Reporting:* Distinguishes `SUCCESS`, `TIMEOUT`, `INVALID`, and `MEMORY_LIMIT`. Timeouts are never recorded or plotted as zero.

### 2.3 Algorithm C — Standard Interval Sweep-Line
- **Mathematical Foundation:**
  - By Helly's property for interval graphs, any family of pairwise intersecting closed intervals has a non-empty common intersection point $x^* \in \mathbb{R}$. Consequently, every maximal clique corresponds to the subset of intervals simultaneously active at some point $x^*$.
  - Over closed intervals, the active set changes only at interval endpoints. A sweep-line from left to right visiting all $2n$ endpoints in order discovers all maximal cliques.
- **Rigorous Mathematical Proof of Correctness:**
  1. *Each active set at an END event is a clique:* When an interval $v$ reaches its right endpoint $r_v$, every interval $u$ currently in the active set has started ($\ell_u \le r_v$) and has not yet ended ($r_u \ge r_v$). Thus $r_v \in \bigcap_{u \in \text{active}} I_u$. By Helly's property, all intervals in the active set pairwise intersect and form a clique.
  2. *Every maximal clique is reported:* Let $K$ be an arbitrary maximal clique of $G$. By Helly's property, the common intersection $\bigcap_{u \in K} I_u$ is a non-empty closed interval $[a, b]$. Let $x^* = b$. Since $b$ is the right boundary of the intersection, there exists at least one interval $v \in K$ whose right endpoint equals $b$ (otherwise every interval in $K$ extends strictly past $b$, contradicting the definition of $b$). At event $r_v$, all vertices of $K$ are in the active set. Furthermore, no vertex $w \notin K$ can be active at $r_v$, because if it were, $K \cup \{w\}$ would be a pairwise intersecting family, contradicting the maximality of $K$. Hence, the active set at event $r_v$ is exactly $K$.
  3. *No non-maximal clique is reported:* Active sets are emitted only upon processing an END event where `hasNewStart == true`. If multiple END events occur consecutively without any intervening START events, the active set at each subsequent END event is a strict subset of the active set at the first END event. By requiring `hasNewStart == true`, all strict subsets are pruned.
  4. *Duplicate cliques are avoided:* Requiring `hasNewStart == true` and immediately setting `hasNewStart = false` ensures that identical active sets cannot be emitted at consecutive events. Moreover, because proper interval graphs have monotonically ordered left and right endpoints ($\ell_1 \le \dots \le \ell_n$ and $r_1 \le \dots \le r_n$), each maximal clique forms a unique contiguous index window that never recurs later in the sweep.
  5. *Closed endpoint touching is handled correctly:* When intervals touch at a single point (e.g. $[a, b]$ and $[b, c]$), the intersection at $x = b$ is non-empty. In Algorithm C, events at the exact same coordinate break ties by placing START events strictly before END events. Consequently, the interval starting at $b$ enters the active set *before* the interval ending at $b$ departs, ensuring both are simultaneously active at $x = b$.
- **Execution Pipeline:**
  - *Preprocessing (`preprocessing_ms`):* Extract $2n$ events (START at $\ell_i$, END at $r_i$) and sort them in $\mathcal{O}(n \log n)$ time.
  - *Core Identification (`core_ms`):* Sweep through the $2n$ sorted events maintaining an active list with $\mathcal{O}(1)$ insertions and deletions. When an END event occurs with `hasNewStart == true`, record the contiguous index range $[first, last]$. Total core time: $\mathcal{O}(n)$.
  - *Materialization (`materialization_ms`):* Expand contiguous ranges into explicit vertex lists. Total materialization time: $\mathcal{O}(S)$.

## 3. Graph Generation Methodology & Overlap Profiles

### 3.1 Interval Model & Overlap Profiles
The primary benchmark uses deterministic equal-length closed intervals:
$$I_i = [i \cdot d, \; i \cdot d + W], \quad i \in \{1, 2, \dots, n\}$$
where $0 < d \le W$.

#### Mathematical Properties
1. **Properness:** For all $i < j$, $\ell_i = i \cdot d < j \cdot d = \ell_j$, and since length $W$ is identical, $r_i = \ell_i + W < \ell_j + W = r_j$. Hence, no interval properly contains another.
2. **Connectedness:** Because $W \ge d$, consecutive intervals satisfy $r_i = i \cdot d + W \ge (i+1) \cdot d = \ell_{i+1}$, ensuring $I_i \cap I_{i+1} \ne \emptyset$.
3. **Bandwidth & Degree:** Two intervals $i$ and $j$ intersect if and only if $|j - i| \le k = \lfloor W / d \rfloor$.

#### Clarification on Graph Density Terminology
The benchmark profiles are designated by their **overlap profile** rather than traditional global graph density:
- **`sparse-overlap` ($k = 1$):** Minimal overlap ($W/d = 1.5$). Path-like structure where each interval intersects only its immediate left and right neighbors. Average degree $\approx 2$. Edge count $m = n - 1$.
- **`medium-overlap` ($k = 8$):** Moderate overlap ($W/d = 8.0$). Each interval intersects up to 8 neighbors on each side. Average degree $\approx 16$. Edge count $m \approx 8n$.
- **`dense-overlap` ($k = 25$):** Heavy local overlap ($W/d = 25.0$). Each interval intersects up to 25 neighbors on each side. Average degree $\approx 50$. Edge count $m \approx 25n$.

**Critical Asymptotic Note:** In all three profiles, the maximum vertex degree is bounded by $2k$, and the total edge count is strictly linear:
$$m = \mathcal{O}(k \cdot n) = \mathcal{O}(n)$$
These graphs are locally dense in terms of clique size ($|C_j| \le k + 1$), but globally sparse ($m = \mathcal{O}(n)$, not quadratic $\Theta(n^2)$).

| Overlap Profile | Step $d$ | Width $W$ | Bandwidth $k$ | Avg Degree ($n \to \infty$) | Max Clique Size $|C_j|$ | Clique Count $q$ | Total Memberships $S$ |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **`sparse-overlap`** | $1.0$ | $1.5$ | $1$ | $\approx 2.00$ | $2$ | $n - 1$ | $2(n - 1)$ |
| **`medium-overlap`** | $1.0$ | $8.0$ | $8$ | $\approx 16.00$ | $\min(n, 9)$ | $\max(1, n - 8)$ | $q \cdot 9$ |
| **`dense-overlap`** | $1.0$ | $25.0$ | $25$ | $\approx 50.00$ | $\min(n, 26)$ | $\max(1, n - 25)$ | $q \cdot 26$ |

Benchmark evaluations spanned 13 orders of magnitude:
$$n \in \{10, 20, 50, 100, 200, 500, 1000, 2000, 5000, 10000, 20000, 50000, 100000\}$$

### 3.2 Expanded Graph Families for Robustness Testing
In addition to the uniform equal-length model, four additional graph families were implemented and verified:
1. **Family 2 (Unequal Lengths):** Intervals have non-uniform lengths $W_i$, constructed such that $\ell_i < \ell_{i+1}$ and $r_i < r_{i+1}$ strictly hold, preserving properness without equal lengths.
2. **Family 3 (Identical Intervals):** Clusters of intervals sharing identical endpoints ($I_i = I_j$), testing lexicographic tie-breaking and non-strict containment.
3. **Family 4 (Endpoint-Touching Intervals):** Consecutive intervals touching at exact single boundary points ($r_i = \ell_{i+1}$).
4. **Family 5 (Randomized Proper Interval Graphs):** Graphs generated by uniformly sampling left endpoints and monotonically increasing lengths across fixed random seeds.

## 5. Timing Methodology & Metrics

### 5.1 Timed Stages & Measurement Protocol
To guarantee total transparency and address the distinction between pre-built data structures and raw input execution, five separate timing metrics are recorded:
1. **`preprocessing_ms`:**
   - *Algorithm A:* Canonical distance tree $T(G)$ construction (two-pointer monotonic scan, level set computation, tree traversal vectors).
   - *Algorithm B:* 0.0 ms (no structural preprocessing).
   - *Algorithm C:* Endpoint event extraction and sorting of $2n$ events.
2. **`core_ms`:** Time to discover the complete family of maximal cliques in compact descriptor format ($[p, c]$ for Alg A; active index range for Alg C).
3. **`materialization_ms`:** Time to allocate and populate the explicit `std::vector<std::vector<int>>` structure for all $q$ cliques.
4. **`postprocessing_total_ms`:** Sum of core identification and materialization:
   $$\text{postprocessing\_total\_ms} = \text{core\_ms} + \text{materialization\_ms}$$
5. **`end_to_end_sum_ms`:** Mathematical sum of all three phases:
   $$\text{end\_to\_end\_sum\_ms} = \text{preprocessing\_ms} + \text{core\_ms} + \text{materialization\_ms}$$
6. **`direct_end_to_end_ms`:** Directly timed in a single continuous measurement block from the input graph to fully materialized output vectors:
   $$\text{Start Timer} \longrightarrow \text{Preprocess} \longrightarrow \text{Core} \longrightarrow \text{Materialize} \longrightarrow \text{Stop Timer}$$

### 5.2 Statistical Protocol
- **Warm-Up:** 1 unrecorded warm-up execution per benchmark configuration to ensure CPU caches and memory pages are hot.
- **Repetitions:** Adaptive iteration counts:
  - $n \le 100$: 20 repetitions
  - $200 \le n \le 1,000$: 10 repetitions
  - $2,000 \le n \le 10,000$: 5 repetitions
  - $n \ge 20,000$: 3 repetitions
- **Aggregation:** Reported metric is the **median** across repetitions, accompanied by minimum and maximum times in the raw CSV.
- **Zero Verification Overhead:** All correctness assertions, graph property checks, and canonical equality verifications were executed strictly **outside** the measured timing blocks.

## 6. Correctness Verification Across Expanded Graph Families

Before collecting performance telemetry, all implementations were subjected to exhaustive mathematical verification via the `--verify` test harness.

### 6.1 Verification Criteria
1. **Canonical Set Equality:**
   $$\text{Canonical}(A) == \text{Canonical}(B) == \text{Canonical}(C)$$
   where $\text{Canonical}$ internally sorts each clique's vertex IDs and lexicographically sorts the family of cliques.
2. **Pairwise Adjacency:** Every clique $C_j$ was validated: $\forall u, v \in C_j, \; I_u \cap I_v \ne \emptyset$.
3. **Maximality:** Verified that $\forall C_j, \; \nexists w \in V \setminus C_j \text{ s.t. } \forall u \in C_j, I_w \cap I_u \ne \emptyset$.
4. **Graph Integrity:** Verified properness ($\nexists i, j \text{ with } I_i \subsetneq I_j$) and connectedness.
5. **Phase 5 Ground Truth:** Outputs were cross-verified against the approved Phase 5 `MaximalCliques::constructCompactCliques` oracle.

### 7.2 Detailed Interpretation of Generated Figures

#### Plot 1 — Direct End-to-End Runtime vs Number of Vertices (`plots/runtime_vs_n.png`)
- **Direct End-to-End Scaling:** Unlike previous reports that excluded preprocessing, Plot 1 now plots strictly `direct_end_to_end_ms`. On log-log axes, Algorithm A and Algorithm C produce straight lines of slope $\approx 1$, confirming empirical linear scaling across six orders of magnitude ($n = 10$ to $n = 100,000$).
- **Direct Comparison at $n = 100,000$:** In medium-overlap, Algorithm C completes full end-to-end execution in **15.02 ms**, while Algorithm A requires **35.25 ms**. The delta ($\approx 20\text{ ms}$) is directly accounted for by Algorithm A's distance tree preprocessing ($24.29\text{ ms}$ vs Algorithm C's endpoint sorting of $6.09\text{ ms}$).
- **Bron–Kerbosch Timeout Cliff:** Algorithm B displays a steep super-linear curve, escalating from $0.0066\text{ ms}$ at $n = 10$ to $95.11\text{ ms}$ at $n = 2,000$, and terminating at the 3,000 ms timeout at $n = 5,000$.

#### Plot 2 — Core Clique Identification Runtime (`plots/core_runtime_vs_n.png`)
- **Core Linearity:** When distance tree preprocessing is complete, Algorithm A's core identification (scanning non-leaf parents via Lemma 3.15) runs in **$7.21\text{ ms}$** for $100,000$ vertices and $99,992$ maximal cliques in medium-overlap (and **$6.26\text{ ms}$** in dense-overlap).
- **Core Parity with Algorithm C:** Algorithm C's core sweep takes **$6.08\text{ ms}$** at $n = 100,000$. Both specialized algorithms identify 100,000 maximal cliques in under 8 milliseconds, demonstrating that both structural tree scanning and event sweeping achieve optimal $\mathcal{O}(n)$ core efficiency.

#### Plot 3 — Output Materialization Overhead (`plots/materialization_vs_n.png`)
- **The Cost of Explicit Vectors:** Plot 3 isolates the time required to materialize explicit vertex lists (`materialization_ms`) versus graph order $n$. Materialization time grows in direct proportion to total memberships $S = \sum |C_j| = \mathcal{O}(k \cdot n)$.
- **Percentage of Postprocessing:** In medium-overlap at $n = 100,000$, materialization requires **$4.24\text{ ms}$** for Algorithm A (37% of postprocessing) and **$3.68\text{ ms}$** for Algorithm C (38% of postprocessing). In dense-overlap ($S = 2,599,350$), materialization rises to **$6.68\text{ ms}$** (52% of postprocessing), exceeding core identification time.

#### Plot 4 — Runtime Comparison Across Overlap Profiles (`plots/density_comparison.png`)
- **Overlap Sensitivity of Specialized Algorithms:** At $n = 100,000$, Algorithm A's direct end-to-end runtime moves from **$34.44\text{ ms}$** in sparse-overlap ($k = 1$) to **$35.25\text{ ms}$** in medium-overlap ($k = 8$) and **$39.38\text{ ms}$** in dense-overlap ($k = 25$). This minor increase reflects only the expanded vector allocation for larger cliques ($S$ growing from $200,000$ to $2,599,350$).
- **Severe Degradation of Bron–Kerbosch:** In contrast, Bron–Kerbosch is acutely sensitive to overlap: at $n = 2,000$, BK requires **$66.50\text{ ms}$** in sparse-overlap, **$95.11\text{ ms}$** in medium-overlap, and **$350.13\text{ ms}$** in dense-overlap.

## 9. Practical Scalability Limits of Bron–Kerbosch

### 9.1 Algorithmic Bottlenecks of Backtracking on Interval Graphs
Although Algorithm B incorporates Tomita pivot selection to minimize recursive branching, it degraded exponentially relative to the specialized interval algorithms:
1. **Recursive State Stack Overhead:**
   Even when the recursion tree is pruned, partitioned candidate vectors $P$ and exclusion vectors $X$ are allocated and filtered at every stack frame. At $n = 2,000$ in dense-overlap, thousands of recursive invocations occur, incurring substantial heap reallocation and CPU cache churn.
2. **Quadratic Pivot Selection:**
   Finding the Tomita pivot requires maximizing $|P \cap N(u)|$ over $u \in P \cup X$. In dense graphs where $|P| \approx 50 - 100$, computing neighbor intersections requires $\mathcal{O}(|P \cup X| \cdot |P|)$ operations at each search node.
3. **Absence of Global Coordinate Awareness:**
   Bron–Kerbosch treats the graph as an arbitrary topology, entirely oblivious to the 1D geometric ordering of intervals. It spends computation rediscovering local cliques that the geometric ordering exposes trivially.

### 9.2 Measured Scalability Limit
- At $n = 2,000$ in dense-overlap, Bron–Kerbosch required **$350.13\text{ ms}$** — over $890\times$ slower than Algorithm A's direct end-to-end time ($0.3907\text{ ms}$).
- At $n = 5,000$, Bron–Kerbosch exceeded the 3,000 ms timeout limit across all three overlap profiles and aborted.
- **Empirical Boundary:** Under modern desktop hardware conditions, $n = 2,000$ represents the absolute practical limit for standard pivoted Bron–Kerbosch. Extrapolating its polynomial growth to $n = 100,000$ yields projected runtimes exceeding hours or days.

## 10. Rigorous Theoretical Complexity Derivations

### 10.1 Correcting Complexity & Space Claims
Prior drafts occasionally used imprecise terminology such as "exponential space saving." This claim is mathematically incorrect and is hereby formally corrected:
- In proper interval graphs, the number of maximal cliques is at most $n$ ($q \le n$).
- Compact descriptors store 2 integers per clique: space is $\mathcal{O}(q) = \mathcal{O}(n)$.
- Explicit materialization stores all memberships: space is $\mathcal{O}(S) = \mathcal{O}(\sum |C_j|)$.
- The compression ratio between explicit and compact representations is:
  $$\text{Compression Ratio} = \frac{S}{q} = \text{Average Clique Size} \approx k + 1$$
  This ratio is **polynomial** (strictly linear in bandwidth $k$), never exponential.
- **Materialization Savings:** Materialization time ($\mathcal{O}(S)$) and space are avoided **only if** downstream consumers (e.g. coloring, independent set) operate directly on the compact index descriptors $[p, c]$. If explicit vertex sets are required, the $\mathcal{O}(S)$ cost is unavoidable.

### 10.2 Algorithm A Complexity Derivation
Let $G = (V, E)$ have $|V| = n$ vertices pre-sorted by left endpoints.
1. **Distance Tree Construction:**
   - Parent assignment: two-pointer monotonic scan advances the candidate parent pointer at most $n$ times across the $n$ loop steps. Time: $\mathcal{O}(n)$.
   - Level BFS and traversals: visits each node and tree edge once. Time: $\mathcal{O}(n)$.
   - Total Preprocessing Time: $\mathcal{O}(n)$.
2. **Lemma 3.15 Core Identification:**
   - Scans $p = 1 \dots n$.
   - Checks `pNode.childrenIds.empty()` in $\mathcal{O}(1)$ time.
   - Retrieves rightmost child $c = \text{childrenIds.back()}$ in $\mathcal{O}(1)$ time.
   - Emits descriptor $[p_{\text{idx}}, c_{\text{idx}}]$ in $\mathcal{O}(1)$ time.
   - Total Core Time: $\mathcal{O}(n)$.
   - Space for Descriptors: $\mathcal{O}(q)$ where $q \le n$.
3. **Explicit Materialization:**
   - For each clique $j \in \{1, \dots, q\}$, iterates over indices from $p_{\text{idx}}$ to $c_{\text{idx}}$.
   - Total Materialization Time: $\sum_{j=1}^q (c_{\text{idx}} - p_{\text{idx}} + 1) = \sum_{j=1}^q |C_j| = \mathcal{O}(S)$.
4. **Overall Complexity:**
   - *Compact Mode:* $\mathcal{O}(n)$ time, $\mathcal{O}(n)$ space.
   - *Materialized Mode:* $\mathcal{O}(n + S)$ time, $\mathcal{O}(S)$ space.

### 10.3 Algorithm C Complexity Derivation
1. **Event Extraction and Sorting:**
   - Generates $2n$ events from $n$ intervals in $\mathcal{O}(n)$ time.
   - Sorts events with `std::sort`: $\mathcal{O}(n \log n)$ time.
2. **Sweep-Line Core Traversal:**
   - Iterates through $2n$ events sequentially.
   - START event: appends vertex to doubly-linked list and stores list iterator in handle table in $\mathcal{O}(1)$ time.
   - END event: if `hasNewStart == true`, emits $[first, last]$ from list ends in $\mathcal{O}(1)$ time, resets `hasNewStart = false`, and erases departing vertex in $\mathcal{O}(1)$ time.
   - Total Core Time: $2n \times \mathcal{O}(1) = \mathcal{O}(n)$.
3. **Explicit Materialization:**
   - Expands contiguous range $[first, last]$: $\mathcal{O}(S)$ time.
4. **Overall Complexity:**
   - *Compact Mode:* $\mathcal{O}(n \log n)$ time, $\mathcal{O}(n)$ space.
   - *Materialized Mode:* $\mathcal{O}(n \log n + S)$ time, $\mathcal{O}(S)$ space.

### 10.4 Algorithm B Complexity Derivation
- On general graphs, Bron–Kerbosch with pivoting has a worst-case time bound of $\mathcal{O}(3^{n/3})$ (Tomita et al., 2006).
- On proper interval graphs, although $q \le n$, the recursive branching tree must still evaluate candidate intersections:
  $$T(n) = \sum_{\text{recursive states } \tau} \mathcal{O}(|P_\tau \cup X_\tau| \cdot |P_\tau|)$$
- In bounded-degree interval graphs, the branching depth is bounded by clique size $\approx k$, but the total number of subproblems and intersection tests scales super-linearly, yielding steep empirical polynomial growth ($\approx \mathcal{O}(n^3) - \mathcal{O}(n^4)$) and rapid timeout.

## 11. Limitations and Threats to Validity

1. **Pre-Sorted Input Requirement:**
   Both Algorithm A and Algorithm C assume input intervals are sorted by left endpoints ($\ell_1 \le \dots \le \ell_n$). If raw intervals are presented in arbitrary order, an initial $\mathcal{O}(n \log n)$ sorting pass must precede both algorithms.
2. **Deep Linear Trees & Thread Stack Limits:**
   In path-like graphs (`sparse-overlap`, $k = 1$), the distance tree degenerates into a single chain of depth $n$. At $n = 100,000$, recursive pre/post-order traversals in `DistanceTree` exceed the default Windows 1 MB stack. This was resolved by configuring `/STACK:67108864` (64 MB). In non-research production code, an iterative DFS or Morris traversal should replace recursion to guarantee $\mathcal{O}(1)$ stack usage.
3. **Synthetic Deterministic Structure:**
   While the benchmark suite validated 5 distinct families (including randomized and unequal lengths), the large-scale performance benchmarking ($n = 10 \dots 100,000$) utilized uniform equal-length intervals. However, because Lemma 3.15 depends solely on parent-child relationships and contiguous index ranges, performance on arbitrary proper interval graphs with identical $(n, m, k)$ is mathematically identical.
4. **Platform & Compiler Specifics:**
   All benchmarks were measured on MSVC 2022 on an Intel i7-13700H under Windows 11. While microarchitectural constants differ across Linux/GCC or Apple Silicon/Clang, the asymptotic relative speedups between $\mathcal{O}(n)$ and exponential backtracking are hardware-invariant.
